### C 的职责与通用能力边界

- C 仍专注分类，不扩展回归、聚类等不在本次作业范围内的任务。
- 必须同时覆盖二分类和多分类，处理类别不平衡、非数值原始标签、类别顺序与合法概率；不存在的类别或未声明输出要明确拒绝。
- 模型注册表加入 `input_kind`/`representation`、所需输入字段、稠密/稀疏支持和输出能力。B 提供版本化表示，A 在能力范围内自主选择，C 校验后执行。
- 表格路径先接四类模型；文本路径可规划“仅 train 拟合的文本特征化 + 分类器”的完整 Pipeline，需 B/C/预测入口共同设计稀疏数据协议，不能强行套用当前 dense-only 表格协议。
- 图像路径先定义输入形状、通道、类别和运行资源约定，再根据已发布任务选择通用基线；未经验证不宣称已经支持。使用额外预训练/嵌入模型前，核实课程模型限制的适用范围，不默认任意第三方预训练模型获准。
- 课程列出了可能的模态，并未要求第一批开发一次实现所有模型；应在正式冻结前按任务与风险验证支持范围。不能保证 unseen 一定是表格。
- 自主生成/修改代码是课程允许的方式，不是必须实现的功能。保留受限候选模型的方案可以满足自主选型、实验与反馈迭代，但需展示实际决策证据和局限。

### 正式运行与预测交付

- 指定 test 不进入搜索或训练。先自动冻结选中的方案，再由独立预测/最终评估步骤读取所需 test 特征，不能依据 test 分数重新选模。
- 不把课前写 TaskSpec、声明官方数据路径/列含义视为按任务名特制算法；但不能在输入配置里人工指定该数据集的已知最佳解法来替代自主搜索。
- 实施前统一任意原始标签到编码类别的映射，最终按任务规定反映射并输出规定的 sample ID、类别标签或概率列，而非默认所有任务接受 0/1 编码 CSV。
- formal run 默认从新会话自主执行；跨会话旧结果复用后置，如以后启用，必须符合相同最终系统版本、完整来源和课程运行定义，不能偷偷使用人工挑出的旧模型。
- 通用的多 seed 复核和自动选模政策可在运行前固定；正式运行中不根据一次结果手工增大 patience、换模型或挑最终产物。
- 24 小时是 unseen 的整体截止期限，不是允许单个 C 训练占满 24 小时；main 应留出预测、结果格式检查和交付时间。

### 预算和模型资格：正式运行前置条件

- 课程原文要求使用 2026-10-21 或之前正式发布且有官方标准 API 价格的 Qwen/DeepSeek 模型。当前配置的 `DeepSeek-V4.1-Flash` 名称、发布时间、官方模型对应关系、官方标准输入输出价格尚未核验，不据此宣称符合要求。

- 开发调试、多次正式尝试具体如何归属每任务额度需按课程说明统一记录；绝不能把“每次重启”自行等同“新任务获 20 元”。C 的本地传统分类器训练耗时与 LLM token 费用分别报告。

## 1. 目标和现有基线

将 C 从支持两模型的固定训练 worker，增强为面向二分类/多分类、具备统一能力声明、可按输入表示扩展、多模型执行、资源与诊断记录和可靠工件交付的实验执行模块。四类表格模型是第一批可运行能力，不代表完整课程范围。A 继续负责选择方案，B 负责预处理，D 负责独立评分和 API 记账。

真实基线为 `session_20261113T145539Z_efd01c58`：5 轮训练，最佳 validation accuracy 为 0.7512315270935961；最佳模型是 200 棵树、无限深度、叶子最少 1 个样本的随机森林。5 次 API 调用按开发配置估算为 0.0060775 元，并非学校正式费用核验。停止原因是 A 的 `patience=4`：连续 4 轮没有超过第 1 轮，而非预算耗尽。

### 已经具备、应继续保留的能力

- 固定白名单模型/参数校验，不执行 A 生成的代码。
- 子进程训练、超时终止、线程限制；唯一实验目录、拒绝覆盖历史。
- stdout/stderr、总耗时、源码快照及哈希、环境版本记录。
- 模型序列化和同进程重载探测、父进程产物检查、预测概率及类别顺序校验。
- `result.json` 原子发布；main 冻结最佳模型与 B 预处理器；集成测试覆盖新进程预测。
- A 已有当前会话内模型/参数去重。C 的唯一 experiment ID 校验则用于防覆盖，两者作用不同。

### 已核实的限制

- C 只有 random_forest 和 logistic_regression；前者 3 个、后者 2 个可调参数。
- `contracts.py` 和 `capabilities.json` 重复表达能力，测试检查一致性；模型构造另有 if/elif。
- 现有参数校验主要覆盖整数、可空整数和正数，扩展枚举、布尔、联合类型前需完善校验。
- A 的 LLM 提示词、回复校验、规则搜索空间均写死两模型。只修改 C 的 JSON 不足以接通新模型。
- A 默认 patience=4，main 未提供其配置入口；更多模型可能尚未被试到就提前停止。
- B 输出 train 拟合的稠密 float64 独热矩阵，当前约 111 列；没有原生类别数据视图。
- main 根据任务配置确定实际随机种子；上游计划自行生成的 seed 不会成为最终 C 计划的种子。

## 2. 第一优先级：统一模型注册和参数协议

建议在现有 `executor_c/` 下新增 `model_registry.py`，不建立新目录。一个注册表维护模型 ID、参数 schema、默认值、输入要求、固定设置与实现版本；训练构造器可以独立延迟加载，避免 A 读取能力时加载所有训练依赖。

- 按课程修订补输入模态/表示和输出能力描述；先保证表格可运行，文本/图像适配不能通过静默转为稠密数值矩阵冒充支持。
- `capabilities()` 和可分发的 `capabilities.json` 从同一来源生成。
- C 参数规范化、默认值填充、类型/范围/条件校验使用同一 schema。
- A 直接使用规范化后的 schema 和验证接口，移除两份模型白名单漂移。
- 支持 enum、bool、整数、含 0 的浮点区间、nullable 和必要的联合类型；拒绝未知字段、NaN/Infinity、bool 冒充整数。
- 第一版有意收窄联合类型：例如树的 max_features 先只开放 `sqrt`、`log2`、0.5、1.0，避免一次暴露 sklearn 全部参数组合。
- 不向 A 暴露任意 estimator 路径、脚本、回调、输出路径或不受控的线程数。
- 增加 schema/注册表版本和指纹；旧 plan 缺少新增参数时补默认值，旧 RF/LR 工件继续可加载。
- 更新源码快照范围，新增注册表或辅助模块实际参与执行时也纳入审计，不能只保留原来三份源码快照。

验收：新增一个模型不再需要同步手写多份参数范围；非法计划在 fit 前拒绝；旧 RF/LR 参数保持原行为。

## 3. 第一批模型和搜索参数

第一批使用已有 scikit-learn 依赖，保留 CPU 串行执行。

| 模型 | 地位 | 首批开放参数 |
| --- | --- | --- |
| random_forest | 保留并扩展 | n_estimators、max_depth、min_samples_leaf、min_samples_split、max_features、criterion、class_weight |
| logistic_regression | 保留线性基线 | C、max_iter、class_weight；暂保留固定 lbfgs 与缩放 Pipeline，减少 solver/penalty 兼容组合 |
| extra_trees | 新增 | n_estimators、max_depth、min_samples_leaf、max_features、class_weight |
| hist_gradient_boosting | 新增 | learning_rate、max_iter、max_leaf_nodes、min_samples_leaf、l2_regularization |

初始有限候选（供 A 探索，而非做所有组合的笛卡尔积）：树数量 100/200/400/500，深度 8/16/32/null，叶子样本数 1/2/5/10；HGB 学习率 0.03/0.1/0.2，迭代上限 100/200/400，叶子节点数 15/31/63，L2 0/1/10。具体上限结合训练耗时再调整，不作准确率提升承诺。

HGB 一期明确使用当前数值独热输入，不宣称使用了原生类别建模；设置 categorical_features=None。如启用早停，显式配置训练数据内部的 validation_fraction、种子和停止参数，记录实际迭代数，不向 C 传 D 的外部 validation 标签。默认 `auto` 在当前 8117 个训练样本下不一定启用早停，应避免误以为默认已经生效。

验收：4 个模型都通过合法/非法参数、二分类和小规模多分类数据、训练保存、新进程加载、概率顺序和 D 评分链路；真实开发分区建立可比较基线。

## 4. 让一次实验返回可行动的反馈

建议新增 `executor_c/diagnostics.py`（仍在现有目录），先采用独立、带版本的 `diagnostics.json`，保持 result.json 的既有核心字段稳定。

- 已有 duration_seconds 继续表示执行器端到端耗时；另外记录输入加载、fit、predict、序列化、重载检查的时间。
- 记录模型文件大小、训练/验证特征行列数、输入矩阵字节数、实际 seed、实际线程设置、实际迭代数。
- 捕获收敛及其他训练 warning，记录阶段、类别、限长说明和是否截断，不静默吞掉也不把普通 warning 全部升级为失败。
- 记录失败发生在输入、训练、预测还是保存阶段；只对确能识别的错误分类，未知异常保留原错误信息和日志，不把所有退出码都断言为 OOM。
- 成功和失败都尽力写出诊断；诊断失败不能覆盖原始训练错误。
- 内存监测作为第二步，注明峰值的测量方法、单位、平台和采样局限；缺失写 null，不能冒充 0。

main 读取并筛选反馈后加入 history，A 的 `_map_history` 与 LLM history 构造同步透传。仅写诊断文件而不送入 A 上下文，不算完成反馈闭环。D 当前仅实现 accuracy，修订后由 D 根据各任务公布指标扩展，C 不自行替换独立评分。

验收：可以解释“本轮失败原因是什么”“更慢的模型是否值得继续”“逻辑回归是否未收敛”，并且 A 的 mock 上下文能看到这些反馈。

## 5. 资源控制和结果可靠性

- 保留已有子进程超时机制；分别声明整会话总时长和单实验 timeout 的含义。会话总时长由 main 管理。
- 保留现有单线程默认；并行搜索放后续阶段，避免多模型和 BLAS 叠加使用资源。
- 加训练输入规模预检，限制明显超大稠密矩阵。输入字节数只能用于预检，不能视为模型训练内存峰值的保证。
- 如后期增加强制内存限制，先验证 Linux/Windows 差异和被杀进程的结果处理，再对外声明支持。
- 冻结时仍携带预处理器、模型、计划、类别和特征约定、依赖版本；复制诊断摘要，并纳入新的实现版本。
- 新模型必须同时验证训练时、保存后、全新进程预测三种结果的一致性，不能只以 fit 成功验收。
- 超时/失败不自动扩大资源或重跑；让 A 根据已记录原因提出明确的新实验。

## 6. 去重、复用、复现和可解释性

一期：保留并完善 A 的会话内去重，由 C 生成规范化的实验签名；主循环实际执行的 seed 必须与签名一致。相同参数不同 seed 属于复核实验，不应被误判为重复。

二期：显式启用历史成功结果复用。签名包含训练数据/标签与验证特征/ID 的内容哈希、预处理器哈希、模型和完整默认参数、seed、实现版本和关键依赖版本。实现变化、输入变化、损坏或不完整工件、失败或未知状态均不命中。只引用经校验的成功结果，生成本次独立的引用记录，不覆写旧工件、不冒充新训练；D 使用当前 evaluation manifest 独立评分。跨会话引用及冻结路径处理需要 main 协同，不能只在 C 偷换结果路径。

可选输出树的特征重要性或 LR 系数，映射 B 的特征名称，注明其是模型诊断而非因果解释。训练集诊断指标若以后加入，必须与 D 的 validation accuracy 明确区分，不能参与冒充独立评测。

## 8. 第二阶段与扩展边界

### 原生类别模型

可选 CatBoost 作为后续专项，而非一期强制依赖。B 当前独热编码已经丢失原生类别视图，需新增版本化数据视图，固定列顺序、类别标识、缺失值转换和冻结预测路径。不得直接从 C 绕过 B 任意读 raw 文件。LightGBM/XGBoost 可在基准后按收益与安装复杂度择一，避免一次引入全部依赖。

### 融合模型

先考虑受限的两模型概率平均：A 指定基模型和固定权重，C 输出可独立加载的组合工件，D 独立评分。必须保存所有基模型、类别对齐和预处理版本；新工件协议、路径校验与冻结测试同步更新。初期不加入自动在外部 validation 标签上拟合的 stacking。若以后做 stacking，只在 train 内产生 OOF 训练元模型，预处理必须逐折拟合。

### 训练内交叉验证

不把对 B 全 train 拟合后的矩阵直接切折称为严格无泄漏 CV。真正严格的训练内 CV 需要 B/C 合作，把可拟合预处理 Pipeline 放入每个 fold；默认外部 validation 仍由 D 独立评分。课程已明确允许内部验证程序，无需为常规 train 内 CV 额外寻求许可；按任务公布的划分与资源限制实施即可。

预期新增文件只放现有 executor_c/、scripts/、tests/、docs/ 目录，例如 model_registry.py、diagnostics.py、scripts/report_session.py，以及对应测试。实施时根据实际规模决定拆分，不为了文件数量引入框架。

验证顺序：现有回归测试 → 新模型合成数据和非法方案测试 → timeout/worker 失败/历史不覆盖/输入篡改等必要回归 → 新进程预测 → 一次真实 train/validation 离线基准 → 用户本地显式 school 运行。自动测试用 mock，不读取 key，不发真实模型请求；pytest/ruff 是增强实施的开发检查工具，不要求最终使用者为运行而安装。

可参考一次 30 轮的上限分配：4 个模型各 1 次基线、8 次广度探索、12 次局部优化、6 次对少量优胜方案的多 seed 复核。分配由 A/main 调度，总轮数、停止条件、时间和预算均可能提前终止；不是现在支持的命令，也不是承诺会花完 20 元。反复搜索同一 validation 会增加对该分区的适配，不把微小波动宣传成泛化能力提升。

对比时保留当前 75.12% 作为开发参考，不能以旧版本结果直接代替正式最终版本的报告实验。正式基线/消融可由最终同一程序使用预先定义的通用配置开关运行，必须各自完整自主执行、可溯源且按课程口径计账，不人工拼接最佳片段。按每项任务官方指标报告最终表现、有效方案数、总耗时、失败情况和正式 token 计费。若多 seed 复核，额外报告均值/波动，明确它与当前“按单轮最佳 validation 选冻结模型”的规则不同；改变最终选模政策需 A/main 显式实现。
